# Two-person roadmap

This schedule assumes a 36-hour build window. Adjust to the actual event clock without weakening gates.

## Ownership

Teammate A owns inventory, advisory matching, reachability and planner mechanics. Teammate B owns advisory evidence, independent fixtures, policy checks, report UX and demo evidence. Both review reachability boundaries and security controls.

If skills differ, assign by strength, but keep one TypeScript codebase. Do not introduce Java solely to divide work.

## Schedule

| Time | Teammate A | Teammate B | Joint exit condition |
| --- | --- | --- | --- |
| 0–2h | Finalise data schemas and supported patterns | Map PS requirements and create expected-result manifest | Gate 0 contract written |
| 2–6h | Lockfile inventory and OSV matching | Verify first mappings; report skeleton; policy fixtures | Correct instance/advisory evidence |
| 6–12h | Module/binding/call graph subset | Licence, snapshot and concentration rules; core report views | All core categories functioning or explicitly unknown |
| 12–18h | Fix reachability using training cases | Run held-out cases and security fixtures | Gates 1–4 pass or extras freeze |
| 18–24h | Add bounded candidate engine only if allowed | Candidate comparison and team-fixture execution evidence | Core remains complete; candidate states honest |
| 24–30h | Integration, limits and baseline comparison | Export, usability check, demo data and README | Reproducible end-to-end decision |
| 30–34h | Fix material defects; freeze engine | Pitch/deck preparation and clean demo rehearsal | No critical failed gate |
| 34–36h | Demo support | Demo lead | Clean rerun and offline fallback |

## Priority order

1. Inventory and affected-version correctness.
2. Honest reachability states.
3. All remaining mandatory PS categories.
4. Static-scan security.
5. Evidence report and reproducibility.
6. Bounded bonus planner.
7. Optional LLM explanation and visual polish.

## Backlog

### Must

- Project support summary.
- Exact dependency instances.
- OSV matching.
- Bounded reachability and unknowns.
- Outdated/suspicious/licence/concentration evidence.
- Read-only local report/export.
- Security and validation fixtures.

### Should

- Candidate comparison.
- Team-fixture compatibility results.
- Baseline comparison.
- Stale evidence invalidation.

### Could

- Plain-language LLM explanation.
- Basic second ecosystem inventory/advisory adapter if organisers require it and core gates pass.

### Will not during hackathon

- Arbitrary repository execution.
- Universal reachability.
- Auto-push/merge.
- Enterprise accounts/connectors.
- Legal or security certification.

## Daily control

Keep one task board with `todo`, `in progress`, `review`, `validated` and `deferred`. Only independently checked work enters `validated`. At hour 18, remove unfinished optional features before extending core support.
